# Bangkok Flood Watch 🌧️

เว็บแอปพยากรณ์อากาศและติดตามสถานการณ์น้ำท่วม **กรุงเทพฯ** — รวมพยากรณ์หลายโมเดลแบบ Windy ให้อัตโนมัติ พร้อมจุดน้ำท่วม ที่จอดรถหนีน้ำ และข่าวล่าสุด

## ฟีเจอร์

| แท็บ | รายละเอียด |
|---|---|
| **ภาพรวม** | ดัชนีเสี่ยงน้ำท่วมขัง 24 ชม. (0–100) พร้อมเหตุผลแต่ละปัจจัย, ฝน 24 ชม. ข้างหน้า, โอกาสฝนหนัก, ฝน 6 ชม. ข้างหน้า, สรุปสถานการณ์, ข่าวล่าสุด |
| **พยากรณ์** | กราฟฝนรายชั่วโมง 3 วัน (ค่ากลาง 6 โมเดล + ช่วงต่ำสุด–สูงสุด + โอกาสฝนจาก ensemble), ตาราง 7 วันพร้อมโอกาสฝน ≥10/35/90 มม. และ "ความเห็นตรงกันของโมเดล", แผนที่ Windy |
| **แผนที่** | จุดน้ำท่วม (สีตามความลึก), จุดเฝ้าระวังแม่น้ำ/คลอง, ที่จอดรถหนีน้ำ, ข่าวตามพื้นที่, **กล้อง CCTV (ไอคอนกล้อง)**, เรดาร์ฝนแบบเคลื่อนไหว — จุดน้ำท่วมมีปุ่มดูกล้องที่อยู่ใกล้ |
| **กล้อง CCTV** | กล้องจราจรกรุงเทพฯ/ปริมณฑลจากฟีดสาธารณะ iTIC/Longdo (กรมทางหลวง ฯลฯ) ดูวิดีโอสด HLS หรือภาพนิ่งในแอป + ไลฟ์ YouTube (แม่น้ำเจ้าพระยา สาทร สุขุมวิท) — ตรวจทุกกล้องอัตโนมัติทุก 30 นาที ซ่อนกล้องที่เสีย เรียงจากใกล้พื้นที่ที่เลือก + ลิงก์กล้องทางการ (สำนักการระบายน้ำ กทม., BMA Traffic ฯลฯ) |
| **ที่จอดรถ** | สถานที่เปิดให้จอดรถหนีน้ำ พร้อมสถานะเปิด/ปิดตามวันที่ ปุ่มนำทาง โทร และแหล่งข่าว |
| **ข่าว** | ข่าวอัปเดตอัตโนมัติทุก 30 นาที กรองตามหมวด (ที่จอดรถ/จุดน้ำท่วม/แม่น้ำ/เตือนภัย/ช่วยเหลือ/จราจร) ค้นหาตามเขตหรือถนนได้ |
| **ช่วยเหลือ** | เบอร์ฉุกเฉิน (1555, 1784, 1669 …), Traffy Fondue, เรดาร์ กทม., กรมอุตุฯ, ThaiWater, GISTDA |

เลือกพื้นที่พยากรณ์ได้ทั้ง 50 เขต หรือใช้ตำแหน่ง GPS รองรับมือถือและโหมดมืด

## ทำไมถึงแม่นกว่าดูโมเดลเดียว

สรุปสั้น ๆ (รายละเอียดและงานวิจัยอ้างอิงอยู่ใน **[docs/RESEARCH.md](docs/RESEARCH.md)**):

1. **รวม 6 โมเดล** (ECMWF, UKMO, ICON, GFS, JMA, GEM) ด้วยมัธยฐานถ่วงน้ำหนัก ทำให้โมเดลที่พยากรณ์หลุดมีผลน้อยลง
2. **ความน่าจะเป็นจาก ensemble ~120 สมาชิก** (ECMWF ENS, GEFS, ICON-EPS) เหมาะกับฝนฟ้าคะนองเขตร้อน
3. **เรดาร์สำหรับ 0–2 ชม.** ซึ่งช่วงนี้เรดาร์แม่นกว่าโมเดลเสมอ
4. **ปัจจัยเฉพาะกรุงเทพฯ** ได้แก่ กำลังระบายน้ำ ฝนสะสม น้ำทะเลหนุน และน้ำเหนือ

```
public/                  เว็บ static (ไม่ต้อง build) — deploy โฟลเดอร์นี้
  index.html
  js/config.js           โมเดล น้ำหนัก เกณฑ์ เบอร์ฉุกเฉิน
  js/forecast.js         คณิตศาสตร์รวมโมเดล/ensemble (pure)
  js/analysis.js         รวมทุกอย่างเป็นตัวเลขที่หน้าเว็บแสดง
  js/risk.js             ดัชนีเสี่ยงน้ำท่วมขัง
  js/gazetteer.js        พิกัด 50 เขต + ถนนหลัก สำหรับระบุตำแหน่งจากข่าว
  data/curated.json      ✏️ จุดน้ำท่วม / ที่จอดรถ / สถานการณ์ (แก้ด้วยมือ)
  data/news.json         🤖 ข่าว (สร้างอัตโนมัติ)
  data/cameras.json      ✏️ รายการกล้อง CCTV / ไลฟ์ YouTube (แก้ด้วยมือ)
  data/camera_status.json 🤖 สถานะไลฟ์ของกล้อง YouTube (สร้างอัตโนมัติ)
  data/itic_cameras.json 🤖 กล้องจราจรจาก iTIC/Longdo + ผลตรวจ (สร้างอัตโนมัติ)
scripts/update-news.mjs  ดึงข่าวจาก RSS → news.json
scripts/check-cams.mjs   ตรวจว่ากล้อง YouTube ยังไลฟ์อยู่ → camera_status.json
scripts/update-cams.mjs  ดึงกล้องจราจรจากฟีด iTIC แล้วตรวจว่าเล่นได้จริง → itic_cameras.json
.github/workflows/       CI, ดึงข่าวทุก 30 นาที, deploy GitHub Pages
docs/RESEARCH.md         งานวิจัยและเหตุผล
```

## รันในเครื่อง

```bash
npm install
npm start            # เปิด http://localhost:8080
npm test             # unit tests
npm run update-news  # ดึงข่าวล่าสุดมาใส่ public/data/news.json
npm run check-cams   # ตรวจสถานะไลฟ์ของกล้อง YouTube
npm run update-cams  # ดึง/ตรวจกล้องจราจร iTIC
npm run smoke        # ทดสอบหน้าเว็บจริงใน Chromium (จำลอง API)
```

## Deploy (GitHub Pages — ฟรี)

1. Merge เข้า `main`
2. **Settings → Pages → Source: GitHub Actions**
3. Workflow `Deploy to GitHub Pages` จะ deploy ให้อัตโนมัติ
4. Workflow `Update news data` จะดึงข่าวทุก 30 นาที (GitHub รัน schedule บน `main` เท่านั้น) แล้ว deploy ใหม่

ใช้กับ static hosting อื่นได้เหมือนกัน (Netlify, Cloudflare Pages, Vercel) โดยชี้ไปที่โฟลเดอร์ `public/`

## อัปเดตจุดน้ำท่วม / ที่จอดรถ (ผู้ดูแล)

แก้ `public/data/curated.json` แล้ว commit:

- `floodPoints[]` — จุดน้ำท่วม: `name`, `district`, `lat`, `lon`, `depthCm: [ต่ำ, สูง]`, `status` (`active` / `receding` / `cleared`), `reportedAt`, `source`
- `parking[]` — ที่จอดรถ: `name`, `area`, `lat`, `lon`, `capacity`, `floors`, `from`, `until` (YYYY-MM-DD), `conditions`, `contact`, `inBangkok`, `source`
- `watchPoints[]` — จุดเฝ้าระวังแม่น้ำ/คลอง
- `riverAlert` — ระดับเตือนแม่น้ำเจ้าพระยา 0–3 (ใช้ในดัชนีเสี่ยง) ตั้งตามประกาศกรมชลประทาน/กทม.
- `situation` — สรุปสถานการณ์และแหล่งข่าว

### เพิ่มกล้อง (`public/data/cameras.json`)

```json
{ "id": "yt-xxx", "type": "youtube", "name": "ชื่อกล้อง", "area": "เขต/ย่าน",
  "lat": 13.72, "lon": 100.51, "videoId": "รหัสวิดีโอ 11 ตัว", "channel": "@handle หรือ null",
  "tags": ["river" | "road" | "news"], "note": "คำอธิบาย" }
```

- `videoId` คือส่วนท้ายของลิงก์ `youtube.com/watch?v=...` — ใส่เฉพาะไลฟ์ที่ **อนุญาตให้ฝัง (embed)** ได้
- ใส่ `channel` ไว้ด้วยถ้ารู้ เพราะไลฟ์ใหม่จะได้ videoId ใหม่ ระบบจะหาไลฟ์ล่าสุดของช่องให้เองทุก 30 นาที
- `lat`/`lon` เป็น `null` = แสดงเฉพาะในแท็บกล้อง ไม่ขึ้นบนแผนที่
- กล้องของ กทม. (BMA Traffic / สำนักการระบายน้ำ) ฝังในเว็บอื่นไม่ได้ ให้ใส่ใน `officialSources` เป็นลิงก์

ที่จอดรถจะแสดง "ปิดแล้ว" เองเมื่อเลยวันที่ `until` จุดที่ `status: "cleared"` จะไม่แสดงบนแผนที่

> ข้อมูลตั้งต้นรวบรวมจากข่าววันที่ 25 ก.ย. 2569 และพิกัดบางจุดเป็นค่าประมาณ (มีป้าย `approximate`)

### ผลตรวจกล้องจราจร

ระบบตรวจทุกกล้องทุก 30 นาที: เพลย์ลิสต์วิดีโอ HLS ต้องมีช่วงวิดีโอจริง หรือภาพนิ่งต้องเป็นรูปจริง
- ✅ ใช้ได้ → แสดงในแอป
- ❌ เสีย (ตอบกลับแต่ไม่มีภาพ) → ซ่อน
- ❔ ตรวจไม่ได้ (เซิร์ฟเวอร์ GitHub ในต่างประเทศเชื่อมต่อไม่ได้ บางกล้องรับเฉพาะผู้ใช้ในไทย) → ซ่อนไว้ ผู้ใช้เลือกแสดงเองได้

กล้อง BMA Traffic ของ กทม. ป้องกันด้วย Cloudflare ดึงรายชื่ออัตโนมัติไม่ได้ จึงให้เป็นลิงก์เปิดในเว็บ กทม.

## ข้อจำกัดความรับผิดชอบ

ข้อมูลในแอปนี้ใช้ประกอบการตัดสินใจเท่านั้น **ไม่ใช่ประกาศทางการ** ให้ยึดประกาศของกรุงเทพมหานคร กรมอุตุนิยมวิทยา กรมชลประทาน และ ปภ. เป็นหลัก เหตุฉุกเฉินโทร **1555** (กทม.) หรือ **1784** (ปภ.)
